# Memory Management

> Arena allocators — Allocate by lifetime, free in bulk

---

## Overview

Polaris uses **arena allocators** for temporary memory. Instead of scattered malloc/free calls, memory is organized by lifetime:

- **Permanent arena** — Lives forever (lookup tables, registrations)
- **Phase arenas** — Reset after each frame callback (temp buffers, query results)

This approach eliminates:
- Memory fragmentation
- Forgotten free() calls (memory leaks)
- Use-after-free bugs
- Per-object allocation overhead

---

## What is an Arena?

An arena is a large pre-allocated block of memory. You carve out pieces by bumping a pointer. When done, reset the pointer to free everything at once.

```cpp
struct Arena {
    uint8_t* base;      // Start of memory block
    size_t offset;      // Current allocation position
    size_t capacity;    // Total size
};

// Allocate: just bump the pointer
void* arena_alloc(Arena* a, size_t size, size_t align) {
    size_t aligned_offset = (a->offset + align - 1) & ~(align - 1);
    if (aligned_offset + size > a->capacity) return nullptr;  // OOM
    void* ptr = a->base + aligned_offset;
    a->offset = aligned_offset + size;
    return ptr;
}

// Free everything: just reset the pointer
void arena_reset(Arena* a) {
    a->offset = 0;
}
```

### Why Phase Arenas?

**Without arenas**, every system would need to:
```cpp
void bad_system(flecs::iter& it) {
    std::vector<Entity> temp;  // malloc every frame!
    // ... use temp ...
}  // destructor frees - but this happens EVERY FRAME
```

**Problems:**
- `malloc/free` every frame is **slow** (~50-200 cycles vs ~5-10 for arena)
- Memory **fragmentation** degrades performance over time
- Easy to **forget to free** → memory leaks
- **Cache misses** from scattered allocations

**With arenas**, systems get fast, safe temporary memory:
```cpp
void good_system(flecs::iter& it) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;
    Entity* temp = arena_alloc(arena, count * sizeof(Entity), alignof(Entity));
    // ... use temp ...
}  // NO FREE - arena resets automatically at phase end
```

**Benefits:**
1. **Performance** - O(1) allocation, contiguous memory, cache-friendly
2. **Safety** - Impossible to leak, impossible to use-after-free
3. **Simplicity** - No manual `free()`, no lifetime tracking

> **See:** [examples/arena_usage.cpp](examples/arena_usage.cpp) for detailed comparisons and patterns

### Runtime Structure

```cpp
namespace Polaris {

enum PhaseType {
    Phase_Input,      // _input() - event driven
    Phase_Physics,    // _physics_process() - fixed timestep
    Phase_Process,    // _process() - variable timestep
    Phase_Count
};

struct Phase {
    Arena arena;
    flecs::entity id;   // For system ordering
};

// Runtime is a Godot Object (see 1.2 Core Classes.md)
class Runtime : public Object {
    GDCLASS(Runtime, Object)
public:
    flecs::world world;
    Phase phases[Phase_Count];
    Arena permanent;

    uint64_t frame;
    uint64_t physics_frame;
};

}
```

## Using Arenas

### Get the Current Phase Arena

```cpp
// Inside a system running in Phase_Physics
Arena* arena = &runtime()->phases[Phase_Physics].arena;
```

### Allocate Temporary Data

```cpp
void find_targets_system(flecs::iter& it, AI* ai, Gd::Node3D* node) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;

    // Allocate temp array (freed automatically at phase end)
    const int max_targets = 32;
    flecs::entity* targets = (flecs::entity*)arena_alloc(
        arena,
        max_targets * sizeof(flecs::entity),
        alignof(flecs::entity)
    );

    if (!targets) {
        // Arena full - this shouldn't happen with proper sizing
        return;
    }

    int target_count = 0;

    for (auto i : it) {
        // Find nearby enemies, store in targets array
        // ...
    }

    // Use targets array
    // ...

    // No free() needed - arena resets at phase end
}
```

### Allocate from Permanent Arena

```cpp
// During initialization - this memory lives forever
void register_lookup_table(Runtime* rt) {
    Arena* perm = &rt->permanent;

    // Allocate lookup table that persists
    LookupEntry* table = (LookupEntry*)arena_alloc(
        perm,
        1024 * sizeof(LookupEntry),
        alignof(LookupEntry)
    );

    // Initialize table...
}
```

## When to Use Each Arena

| Arena | Lifetime | Use For |
|-------|----------|---------|
| `permanent` | Application lifetime | Lookup tables, string interning, registered data |
| `phases[Phase_Input].arena` | Single _input() call | Input event buffers |
| `phases[Phase_Physics].arena` | Single _physics_process() | Query results, AI decision data, collision lists |
| `phases[Phase_Process].arena` | Single _process() | Interpolation buffers, UI temp strings |

### Decision Guide

```
Need memory for...

├── The entire application?
│   └── Use: permanent arena (or regular allocation)
│
├── One frame callback?
│   ├── Input handling? → Use: input arena
│   ├── Game logic?     → Use: physics arena
│   └── Visuals?        → Use: process arena
│
└── Longer than one frame but not forever?
    └── Use: ECS component (entity lifetime)
```

## Arena Sizing

Default sizes are starting points. Monitor usage and adjust.

| Arena | Default Size | Typical Contents |
|-------|--------------|------------------|
| `permanent` | 4 MB | Lookup tables, string pools, registrations |
| `physics` | 1 MB | Query results, pathfinding buffers, AI data |
| `process` | 512 KB | Interpolation arrays, debug draw commands |
| `input` | 64 KB | Input event batches |

### Checking Usage

```cpp
void debug_arena_usage(Runtime* rt) {
    for (int i = 0; i < Phase_Count; i++) {
        Arena* a = &rt->phases[i].arena;
        float usage = (float)a->offset / (float)a->capacity * 100.0f;
        printf("Phase %d: %.1f%% (%zu / %zu bytes)\n",
               i, usage, a->offset, a->capacity);
    }
}
```

## What NOT to Store in Arenas

| Don't Store | Why | Instead |
|-------------|-----|---------|
| Persistent game state | Arena resets | ECS components |
| Entity references that outlive frame | Dangling after reset | `flecs::entity` IDs |
| Resources (textures, meshes) | Need proper lifetime | Godot ResourceLoader |
| Handles to external systems | May become invalid | Store in components |

## Performance Notes

### Why Arenas are Fast

1. **Allocation is O(1)** — Just bump a pointer
2. **No fragmentation** — Contiguous memory
3. **Cache friendly** — Allocations are sequential
4. **Deallocation is O(1)** — Just reset one pointer
5. **No per-object overhead** — No headers/footers

### vs malloc/free

```
malloc:
├── Search free list
├── Possibly split block
├── Update metadata
├── May trigger syscall
└── ~50-200 cycles

Arena:
├── Bump pointer
├── Return
└── ~5-10 cycles
```

## Summary

| Concept | Description |
|---------|-------------|
| **Arena** | Pre-allocated block, bump pointer allocation, bulk reset |
| **Permanent** | Never reset, for long-lived data |
| **Phase arenas** | Reset each frame callback, for temp data |
| **Usage** | `arena_alloc()` to get memory, automatic reset at phase end |
| **Benefit** | Fast, no fragmentation, no leaks, cache-friendly |
