# Coding Standards

> C99-style C++ — Write code that looks like C but compiles as C++

---

## Overview

Polaris follows **C99-style C++**. This gives you the simplicity and predictability of C with access to Godot's API and C++ conveniences where they help.

The goal is **Data-Oriented Design**: data layout matters, process in bulk, minimize cache misses.

---

## What to Use

| Use | For |
|-----|-----|
| POD structs | All components |
| Plain functions | All systems |
| `flecs::entity` | Entity handles |
| Godot types (Vector3, Transform3D, etc.) | Math in components (they're POD) |
| Direct Godot pointers | Gd:: components |
| Arenas | Temporary allocations |
| Namespaces | Organization (Polaris::, Tag::, Gd::) |
| `enum class` | State machines, flags |

---

## What to Avoid

| Avoid | Why | Instead |
|-------|-----|---------|
| Inheritance for game objects | Hidden behavior, cache unfriendly | Composition via ECS |
| Virtual functions in hot paths | Indirect calls, cache misses | Plain functions |
| `std::vector`, `std::string` in components | Hidden allocations, not POD | Fixed arrays, arena strings |
| RAII in components | Hidden behavior on copy/move | Explicit setup/teardown |
| Scattered malloc/free | Fragmentation, cache misses | Arena allocators |
| Getters/setters | Unnecessary indirection | Direct field access |
| `this->` | Noise | Just use field name |
| Multiple bools for state | Wastes space, unclear | `enum class` |

## Component Guidelines

Components are **POD structs** — plain old data with no hidden behavior.

### Layout Rules

1. **Largest fields first** — reduces padding
2. **Group related data** — better cache behavior
3. **Explicit padding** — document your intent
4. **No pointers to dynamic memory** — use entity IDs or arena allocations

### Good Components

```cpp
// GOOD: POD struct, tightly packed
struct Health {
    float current;    // 4 bytes
    float max;        // 4 bytes
};                    // 8 bytes total

// GOOD: Godot types are POD
struct Velocity {
    godot::Vector3 linear;    // 12 bytes
    godot::Vector3 angular;   // 12 bytes
};                            // 24 bytes total

// GOOD: State as enum, explicit padding
enum class AIState : uint8_t {
    Idle, Patrol, Chase, Attack
};

struct AI {
    flecs::entity target;     // 8 bytes (entity ID, not pointer)
    float timer;              // 4 bytes
    float aggro_range;        // 4 bytes
    AIState state;            // 1 byte
    uint8_t padding[3];       // 3 bytes (explicit)
};                            // 20 bytes total

// GOOD: Fixed-size array for bounded data
struct Inventory {
    flecs::entity items[8];   // 64 bytes
    uint8_t count;            // 1 byte
    uint8_t padding[7];       // 7 bytes
};                            // 72 bytes total
```

### Bad Components

```cpp
// BAD: Multiple bools waste space
struct AIBad {
    bool is_idle;      // 1 byte + 7 padding
    bool is_chasing;   // 1 byte + 7 padding
    void* target;      // 8 bytes (pointer, not ID)
};                     // 24 bytes with padding

// BAD: std::vector is not POD
struct InventoryBad {
    std::vector<Item> items;  // Hidden allocations!
};

// BAD: Pointer to external memory
struct MeshBad {
    Vertex* vertices;   // Who owns this? When freed?
    size_t count;
};
```

## System Guidelines

Systems are **plain functions** that operate on component data in bulk.

### Function Signature

```cpp
// Preferred: iter-based for bulk processing
void movement_system(flecs::iter& it,
                     Velocity* vel,
                     Gd::CharacterBody3D* body)
{
    for (auto i : it) {
        // Process entity i
    }
}

// Alternative: each-based for simple logic
void health_regen(flecs::entity e, Health& hp, RegenRate& regen) {
    hp.current = fminf(hp.current + regen.rate, hp.max);
}
```

### System Rules

1. **Check validity** — Gd:: components may have null pointers
2. **Process in bulk** — use iter-based systems for performance
3. **Avoid allocations** — use phase arena for temp data
4. **No side effects outside ECS** — except through Gd:: components
5. **Early exit** — skip invalid entities, don't branch inside loops

### Good Systems

```cpp
// GOOD: Bulk processing, validity check, no allocations
void apply_velocity(flecs::iter& it,
                    Velocity* vel,
                    Gd::CharacterBody3D* body)
{
    for (auto i : it) {
        if (!body[i].is_valid()) continue;

        body[i].ptr->set_velocity(vel[i].linear);
        body[i].ptr->move_and_slide();

        // Read back actual velocity after collision
        vel[i].linear = body[i].ptr->get_velocity();
    }
}

// GOOD: Uses arena for temp allocation
void find_nearby_enemies(flecs::iter& it,
                         Gd::Node3D* node,
                         AI* ai)
{
    Arena* arena = &runtime()->phases[Phase_Physics].arena;

    // Temp array freed at phase end
    flecs::entity* nearby = (flecs::entity*)arena_alloc(
        arena, 32 * sizeof(flecs::entity), alignof(flecs::entity)
    );

    for (auto i : it) {
        // Use nearby array...
    }
    // No free needed
}
```

### Bad Systems

```cpp
// BAD: Allocates every frame
void find_nearby_bad(flecs::iter& it, AI* ai) {
    std::vector<Entity> nearby;  // malloc every frame!
    // ...
}

// BAD: Branches inside loop
void process_bad(flecs::iter& it, Health* hp) {
    for (auto i : it) {
        if (hp[i].current > 50) {
            // lots of code
        } else if (hp[i].current > 25) {
            // different code
        } else {
            // more code
        }
    }
}
// BETTER: Split into separate systems with query filters
```

## System Registration

Register systems to specific phases during initialization.

```cpp
void register_movement_systems(Runtime* rt) {
    flecs::entity physics = rt->phases[Phase_Physics].id;

    rt->world.system<Velocity, Gd::CharacterBody3D>("ApplyVelocity")
        .kind(physics)
        .iter(apply_velocity);

    rt->world.system<InputState, MoveSpeed, Velocity, Gd::Node3D>
        ("PlayerMovement")
        .kind(physics)
        .with<Tag::Player>()
        .iter(player_movement);
}
```

## Naming Conventions

| Type | Convention | Example |
|------|------------|---------|
| Components | PascalCase | `Health`, `Velocity`, `AIState` |
| Systems | snake_case function | `apply_velocity`, `check_death` |
| Tags | Tag::PascalCase | `Tag::Player`, `Tag::Dead` |
| Gd components | Gd::NodeType | `Gd::Node3D`, `Gd::CharacterBody3D` |
| Phases | Phase_PascalCase | `Phase_Physics`, `Phase_Input` |
| Arenas | lowercase | `permanent`, `physics`, `process` |

## File Organization

```
game/
├── components/
│   ├── Data.h          # All data components in one header
│   ├── Tags.h          # All tag components
│   └── Gd.h            # Game-specific Gd:: components
│
├── systems/
│   ├── input.cpp       # Phase_Input systems
│   ├── movement.cpp    # Phase_Physics movement
│   ├── combat.cpp      # Phase_Physics combat
│   ├── ai.cpp          # Phase_Physics AI
│   └── animation.cpp   # Phase_Process animation
│
└── compositions/
    ├── Pawn.h/.cpp
    └── PlayerPawn.h/.cpp
```

### Header Guidelines

- **Components**: All in headers (they're just structs)
- **Systems**: Declare registration function in header, implement in cpp
- **One header per concern**: Don't scatter related components

```cpp
// components/Data.h
#pragma once

struct Health {
    float current;
    float max;
};

struct Velocity {
    godot::Vector3 linear;
    godot::Vector3 angular;
};

struct MoveSpeed {
    float value;
};

// ... all data components
```

```cpp
// systems/movement.h
#pragma once

namespace Polaris {
struct Runtime;
}

namespace Game::Systems {
void register_movement_systems(Polaris::Runtime* rt);
}
```

## Summary

| Principle | Practice |
|-----------|----------|
| **Data-Oriented** | POD structs, bulk processing, cache-friendly layout |
| **C99-Style** | Plain functions, no inheritance, explicit memory |
| **Predictable** | No hidden allocations, no hidden behavior |
| **Explicit** | Visible data layout, visible control flow |

Write code that you can reason about by reading it. No magic, no surprises.
