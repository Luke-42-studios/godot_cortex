# Polaris Engine Specification

**Version**: 3.0
**Date**: January 2026
**Status**: Implementation

---

## Overview

> **C**omposition → **E**ntity → **L**ifecycle → **S**ystems
>
> *Define* → *Create* → *Manage* → *Run*

Polaris is a **Data-Oriented** ECS framework built on the **CELS** paradigm. Each layer represents a distinct architectural concern that scales with your game. The framework follows **Data-Oriented C++** — POD structs for data, plain functions for systems, and arena allocators for memory management.

The framework leverages **Flecs** for high-performance entity-component-system processing, keeping gameplay code data-driven and testable. **Godot** serves as the content authoring environment — an IDE for building levels, importing models, creating animations, designing UI, and visualizing your game world.

### Core Principles

| Principle                | What It Means                                                                                                                                       |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Data-Oriented Design** | Data layout matters. Pack structs tightly, process in bulk, minimize cache misses.                                                                  |
| **Simple C++**           | POD structs, plain functions, no inheritance for game objects. Use C++ features (classes, templates) only where they help (Godot API, type safety). |
| **ECS is Truth**         | Game state lives in components. Godot nodes are the "view" — visual representation only.                                                            |
| **Godot as IDE**         | Author content in Godot (scenes, animations, materials). Debug in Godot. But game logic lives in systems.                                           |
| **Arena Memory**         | Temporary memory resets automatically each frame. No manual malloc/free. Fast and leak-proof.                                                       |

## CELS Architecture

The CELS model separates game architecture into four distinct layers. Each layer has a single responsibility, making code easier to understand, test, and maintain.

```
┌────────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│                               POLARIS CELS                                 │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   C - COMPOSITION                                                   │  │
│   │                                                                     │  │
│   │   Compositions are blueprints that define what an entity is made    │  │
│   │   of. They're Godot Resources — editable in the inspector, saved    │  │
│   │   as .tres files. Designers can create variants without code.       │  │
│   │                                                                     │  │
│   │   See: 1.0 Composition.md                                           │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   E - ENTITY                                                        │  │
│   │                                                                     │  │
│   │   Entities are unique IDs that group components together.           │  │
│   │   • Data Components — Pure game state (Health, Velocity)            │  │
│   │   • Gd:: Components — Pointers to Godot nodes (the "view")          │  │
│   │   • Tag Components — Markers with no data (Tag::Player)             │  │
│   │                                                                     │  │
│   │   See: 2.0 Entity.md                                                │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   L - LIFECYCLE                                                     │  │
│   │                                                                     │  │
│   │   Controls when systems run. Phases align with Godot callbacks:     │  │
│   │   _input → _physics_process → _process                              │  │
│   │                                                                     │  │
│   │   See: 3. Lifecycle.md                                              │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   S - SYSTEMS                                                       │  │
│   │                                                                     │  │
│   │   Plain functions that query entities and operate on components.    │  │
│   │   Systems read game state and write to Godot through Gd:: refs.     │  │
│   │                                                                     │  │
│   │   See: 3. Lifecycle.md (System Examples)                            │  │
│   │                                                                     │  │

│                                                                            │
│   ═══════════════════════════════════════════════════════════════════════  │
│                                                                            │
│   CORE RULE: Composition + Godot node = Entity                             │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
```

## Quick Start

```
┌─────────────────────────────────────────────────────────────────────────────┐
│   1. AUTOLOAD        2. COMPOSITION       3. SCENE         4. SYSTEMS       │
│                                                                             │
│   Polaris.tscn  -->  PlayerPawn.cpp  -->  Player.tscn -->  Movement::init() │
│                      (define entity)      (visual)         (game logic)     │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1. Add Autoload

**Project Settings → Autoload → `src/polaris/scenes/Polaris.tscn`**

### 2. Create a Composition

Compositions define what components an entity has.

```cpp
class PlayerPawn : public Pawn {
    GDCLASS(PlayerPawn, Pawn)

public:
    void compose(flecs::entity e, godot::Node* node) override {
        Pawn::compose(e, node);  // Health, Velocity, MoveSpeed, Gd::Node3D
        e.set<InputState>({});
        e.add<Tag::Player>();
    }
};
```

> **See:** [examples/pawn_composition.cpp](examples/pawn_composition.cpp)

### 3. Create Godot Scene

Build your scene in Godot, attach the composition via metadata.

```
PlayerPawn (CharacterBody3D)
├── MeshInstance3D
├── CollisionShape3D
└── AnimationPlayer

metadata["composition"] = PlayerPawn.tres
```

### 4. Write a Domain Module

Systems are organized into domains. Each domain has an `init()` entry point.

```cpp
// systems/movement.cpp
namespace Movement {

static void player_movement(flecs::iter& it, InputState* input,
                            Velocity* vel, Gd::Node3D* node) {
    for (auto i : it) {
        if (!node[i].is_valid()) continue;
        // Apply input to velocity
    }
}

void init(Runtime* rt) {
    rt->world.system<InputState, Velocity, Gd::Node3D>("PlayerMovement")
        .kind(rt->phases[Phase_Physics].id)
        .with<Tag::Player>()
        .iter(player_movement);
}

}
```

> **See:** [examples/domains/movement.cpp](examples/domains/movement.cpp)

### 5. Register All Domains

Wire domains together at startup.

```cpp
void register_game_systems(Runtime* rt) {
    Input::init(rt);
    Movement::init(rt);
    Combat::init(rt);
    AI::init(rt);
    Animation::init(rt);
}
```

> **See:** [examples/domains/game_init.cpp](examples/domains/game_init.cpp)

## Godot as IDE / Debugger

Polaris treats Godot as a content authoring tool and debugger. Game state lives in ECS; Godot nodes are the visual representation.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    MINDSET: GODOT AS IDE / DEBUGGER                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   GODOT PROVIDES:                      POLARIS OWNS:                        │
│   ├── Scene authoring (.tscn)          ├── Game state (ECS components)      │
│   ├── Animation editor                 ├── Game logic (systems)             │
│   ├── Material/shader editor           ├── Entity lifecycle                 │
│   ├── Inspector debugging              └── Memory management (arenas)       │
│   ├── Servers (Rendering, Physics, Audio)                                   │
│   └── Frame callbacks (_process, etc.)                                      │
│                                                                             │
│   DATA FLOW:                                                                │
│                                                                             │
│   ECS (Truth)              Gd:: Component           Godot (View)            │
│   ┌──────────┐            ┌──────────────┐         ┌──────────────┐         │
│   │ Velocity │──system───>│ Gd::CharBody │────────>│ CharBody3D   │         │
│   │ {5,0,0}  │  reads     │ ->set_vel()  │  calls  │ move_slide() │         │
│   └──────────┘            └──────────────┘         └──────────────┘         │
│                                                                             │
│   No sync phase. Systems directly call Godot through Gd:: components.       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### ECS ↔ Godot Boundary

| Direction | Mechanism | When | Example |
|-----------|-----------|------|---------|
| **Godot → ECS** | Composition metadata | Node enters tree | `CompositionFactory` calls `compose()` |
| **Godot → ECS** | Input singleton | Phase_Input systems | `Input::get_singleton()->get_vector()` |
| **Godot → ECS** | Node signals | Via Composition | Connect in `compose()`, store in component |
| **ECS → Godot** | Gd:: component methods | Systems call during phases | `node[i].set_position(...)` |
| **ECS → Godot** | Server singletons | Any system | `PhysicsServer3D::get_singleton()` |

> **See:** [2.0 Entity.md](2.0.Entity.md#entity--node-lookup) for lookup patterns and invalidation guarantees

## Engine Architecture

Polaris runs as a Godot autoload. The core is `Polaris::Runtime` — managed by `PolarisEngine` (a Godot singleton), it owns the flecs world and phase arenas.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           ENGINE ARCHITECTURE                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   GODOT LAYER (GDExtension)                                                 │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                                                                     │   │
│   │   Polaris.tscn (Autoload)                                           │   │
│   │   └── Node "Polaris"                                                │   │
│   │       ├── PipelineNode        → Calls runtime_tick() per phase      │   │
│   │       └── CompositionFactory  → Watches tree, calls compose()       │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   POLARIS RUNTIME (Managed by PolarisEngine singleton)                      │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                                                                     │   │
│   │   Polaris::Runtime                                                  │   │
│   │   ├── flecs::world                                                  │   │
│   │   ├── phases[]                                                      │   │
│   │   │   ├── [Input]   { arena: 64KB,  phase_id }                      │   │
│   │   │   ├── [Physics] { arena: 1MB,   phase_id }                      │   │
│   │   │   └── [Process] { arena: 512KB, phase_id }                      │   │
│   │   └── permanent arena: 4MB                                          │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   See: 1.2 Core Classes.md for Runtime structure and API                    │
│   See: 5. Memory Management.md for arena details                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Setup

Add `src/polaris/scenes/Polaris.tscn` to **Project → Project Settings → Autoload**.

## Entity Creation Flow

When a node with `composition` metadata enters the scene tree, CompositionFactory creates an entity and calls `compose()`.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│   ENTITY CREATION FLOW                                                      │
│                                                                             │
│   Godot Node enters tree                                                    │
│   metadata["composition"] = PlayerPawn.tres                                 │
│                     │                                                       │
│                     ▼                                                       │
│   CompositionFactory detects node → Creates flecs::entity                   │
│                     │                                                       │
│                     ▼                                                       │
│   compose() called → Adds Gd::Node, Gd::Node3D, Health, Velocity, Tags      │
│                     │                                                       │
│                     ▼                                                       │
│   Entity ID stored in metadata["entity_id"]                                 │
│   Systems can now query and process this entity                             │
│                                                                             │
│   See: 1.0 Composition.md and 1.1 CompositionFactory.md                     │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Engine Lifecycle

```
┌─────────────────────────────────────────────────────────────────────────────┐
│   ENGINE LIFECYCLE                                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   INITIALIZATION                                                            │
│   1. GDExtension loads, registers classes                                   │
│   2. Runtime created (flecs::world + arenas)                                │
│   3. Polaris.tscn autoload enters tree                                      │
│   4. CompositionFactory binds to SceneTree signals                          │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   FRAME LOOP                                                                │
│   _input(event)           →   runtime_tick(Phase_Input)   → arena reset     │
│   _physics_process(delta) →   runtime_tick(Phase_Physics) → arena reset     │
│   _process(delta)         →   runtime_tick(Phase_Process) → arena reset     │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   SHUTDOWN                                                                  │
│   1. Nodes removed → entities decomposed and destroyed                      │
│   2. runtime_destroy() frees arenas and flecs::world                        │
│                                                                             │
│   See: 3. Lifecycle.md for phase details and system examples                │
│   See: 1.2 Core Classes.md for detailed lifecycle                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## The ECS ↔ Godot Bridge

Gd:: components hold pointers to Godot nodes, allowing systems to read/write the visual representation.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   ECS WORLD                              GODOT SCENE TREE                   │
│   (Data & Logic)                         (Visuals & Physics)                │
│                                                                             │
│   ┌─────────────────┐                    ┌─────────────────────┐            │
│   │ flecs::entity   │    Gd::Node3D      │ CharacterBody3D     │            │
│   │ ┌─────────────┐ │    ┌───────────┐   │ "Player"            │            │
│   │ │ Health      │ │    │ root ─────────────────────────────> │            │
│   │ │ current:100 │ │    └───────────┘   │ ├── MeshInstance3D  │            │
│   │ └─────────────┘ │                    │ └── AnimationPlayer │            │
│   │ ┌─────────────┐ │                    └─────────────────────┘            │
│   │ │ Velocity    │ │                                                       │
│   │ └─────────────┘ │    Systems read Velocity, call                        │
│   │ ┌─────────────┐ │    Gd::Node3D methods to move Godot node.             │
│   │ │ Tag::Player │ │                                                       │
│   │ └─────────────┘ │                                                       │
│   └─────────────────┘                                                       │
│                                                                             │
│   See: 2.0 Entity.md for Gd:: component details                             │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Directory Structure

```
polaris/
├── src/
│   ├── core/                    # Runtime, PipelineNode, CompositionFactory
│   ├── memory/                  # Arena allocator
│   ├── composition/             # Composition base class
│   ├── components/              # Gd::, Data, Tags
│   └── polaris_init.h           # Module entry point
├── scenes/
│   └── Polaris.tscn             # Autoload scene
└── third_party/
    └── flecs/                   # Flecs ECS library
```

### Your Game Structure

```
src/
├── pawn/                        # Pawn entity domain
│   ├── Components.h             # Shared components (Health, Velocity, PawnMovement)
│   ├── Pawn.h                   # Base pawn composition
│   ├── Pawn.cpp
│   └── player/                  # Player-specific subdomain
│       ├── PlayerComponents.h   # Player components (PlayerInputState, PlayerLook)
│       ├── PlayerPawn.h         # Player pawn composition
│       ├── PlayerPawn.cpp
│       └── PlayerSystems.cpp    # Player systems (input, movement)
├── GameInit.h                   # System registration entry point
└── register_types.cpp           # Godot class registration

resources/
└── pawn/
    └── player_pawn.tres         # Composition instance
```

**Naming Convention:** Use PascalCase for all C++ file names (e.g., `CompositionFactory.h`, `Runtime.cpp`).
