# Polaris Engine Specification

**Version**: 2.0
**Date**: January 2026
**Status**: Implementation

---

## Overview

> **C**omposition → **E**ntity → **L**ifecycle → **S**ystems
>
> *Define* → *Create* → *Manage* → *Run*

Polaris is a lightweight ECS framework built on **CELS** — each layer represents a distinct architectural concern that can be composed together as games scale. It provides a programming-centric approach to game development, following C++ best practices for clean, maintainable game logic.

The framework leverages **Flecs** for high-performance entity-component-system processing, keeping gameplay code data-driven and testable. **Godot** serves as the content authoring environment—an IDE for building levels, importing models, creating animations, designing UI, and visualizing your game world.

This paradigm lets programmers focus on robust, scalable code while using the engine's editor for what it does best: authoring and iterating on game content.

## CELS Architecture

The CELS model separates game architecture into four distinct layers. Each layer has a single responsibility, making code easier to understand, test, and maintain.

```
┌────────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│                               POLARIS CELS                                 │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   C - COMPOSITION                                                   │  │
│   │                                                                     │  │
│   │   Compositions are blueprints that define what an entity is made    │  │
│   │   of. They're Godot Resources — editable in the inspector, saved    │  │
│   │   as .tres files. Designers can create variants (grunt.tres,        │  │
│   │   boss.tres) without touching code.                                 │  │
│   │                                                                     │  │
│   │   When a Godot node has a Composition attached, it becomes an       │  │
│   │   entity in the ECS world.                                          │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   E - ENTITY                                                        │  │
│   │                                                                     │  │
│   │   Entities are unique IDs that group components together. They      │  │
│   │   have no behavior — just an ID. All game state lives in            │  │
│   │   components attached to entities.                                  │  │
│   │                                                                     │  │
│   │   Three component types:                                            │  │
│   │   • Data Components — Pure game state (Health, Velocity)            │  │
│   │   • Gd:: Components — Pointers to Godot nodes (the "view")          │  │
│   │   • Tag Components — Markers with no data (Tag::Player)             │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   L - LIFECYCLE                                                     │  │
│   │                                                                     │  │
│   │   The Lifecycle layer controls when systems run. Polaris aligns     │  │
│   │   with Godot's frame callbacks — _input, _physics_process, and      │  │
│   │   _process — ensuring ECS logic runs at the right time.             │  │
│   │                                                                     │  │
│   │   Systems run in registration order, giving you deterministic       │  │
│   │   execution without complex dependency management.                  │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │                                                                     │  │
│   │   S - SYSTEMS                                                       │  │
│   │                                                                     │  │
│   │   Systems contain your game logic. They query for entities with     │  │
│   │   specific components and operate on them. A movement system        │  │
│   │   queries for (Position, Velocity) and updates positions.           │  │
│   │                                                                     │  │
│   │   Systems read game state from Data Components and write to         │  │
│   │   Godot nodes through Gd:: Components — keeping logic separate      │  │
│   │   from presentation.                                                │  │
│   │                                                                     │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                            │
│   ═══════════════════════════════════════════════════════════════════════  │
│                                                                            │
│   CORE RULE:                                                               │
│   Composition + Godot node = Entity                                        │
│   The Composition's compose() defines what components are added.           │
│                                                                            │
└────────────────────────────────────────────────────────────────────────────┘
```

## Engine Architecture

Polaris runs as a Godot autoload with two child nodes that bridge the scene tree to the ECS world.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           ENGINE ARCHITECTURE                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   AUTOLOAD (Polaris.tscn)                      SINGLETONS                   │
│   ┌─────────────────────────────┐          ┌─────────────────────────┐      │
│   │  Node "Polaris"             │          │  PolarisEngine          │      │
│   │  ├── PipelineNode ──────────────────────> └─ ECSWorld            │      │
│   │  │   • _process()           │          │      └─ flecs::world    │      │
│   │  │   • _physics_process()   │          │                         │      │
│   │  │   • _input()             │          └─────────────────────────┘      │
│   │  │                          │                     ▲                     │
│   │  └── CompositionFactory ──────────────────────────┘                     │
│   │      • Watches SceneTree    │          creates/destroys entities        │
│   │      • compose/decompose    │                                           │
│   └─────────────────────────────┘                                           │
│                                                                             │
│   PipelineNode receives Godot's frame callbacks and runs ECS systems.       │
│   CompositionFactory watches for nodes with composition metadata and        │
│   automatically creates entities when they enter the scene tree.            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Setup

Add `src/polaris/scenes/Polaris.tscn` to **Project → Project Settings → Autoload**.

## Entity Creation Flow

When a node with a `composition` metadata enters the scene tree, CompositionFactory automatically creates an entity and calls the composition's `compose()` method to add components.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   ENTITY CREATION FLOW                                                      │
│                                                                             │
│   ┌──────────────┐                                                          │
│   │ Godot Node   │  A node enters the scene tree with                       │
│   │ enters tree  │  metadata["composition"] = some_composition.tres         │
│   └──────┬───────┘                                                          │
│          │                                                                  │
│          ▼                                                                  │
│   ┌──────────────────┐                                                      │
│   │ CompositionFactory│  Detects the node via SceneTree signals             │
│   │ detects node      │  Checks for "composition" metadata                  │
│   └──────┬───────────┘                                                      │
│          │                                                                  │
│          ▼                                                                  │
│   ┌──────────────────┐                                                      │
│   │ Entity created   │  Creates a flecs::entity in ECSWorld                 │
│   │ in ECSWorld      │  Entity gets the node's name                         │
│   └──────┬───────────┘                                                      │
│          │                                                                  │
│          ▼                                                                  │
│   ┌──────────────────┐                                                      │
│   │ compose() called │  Composition adds components to entity:              │
│   │                  │  • Gd::Node (automatic for 3D)                       │
│   │                  │  • Data components (Health, Velocity, etc.)          │
│   │                  │  • Tags (Tag::Player, Tag::Enemy, etc.)              │
│   └──────┬───────────┘                                                      │
│          │                                                                  │
│          ▼                                                                  │
│   ┌──────────────────┐                                                      │
│   │ Entity ID stored │  Node gets metadata["entity_id"] for reverse lookup  │
│   │ on node          │  Systems can now query and process this entity       │
│   └──────────────────┘                                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

When the node exits the scene tree, the reverse happens: `decompose()` is called to clean up, then the entity is destroyed.

## Engine Lifecycle

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   ENGINE LIFECYCLE                                                          │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ INITIALIZATION                                                      │   │
│   │                                                                     │   │
│   │   1. GDExtension loads                                              │   │
│   │      Polaris registers its classes with Godot                       │   │
│   │                                                                     │   │
│   │   2. PolarisEngine singleton created                                │   │
│   │      Creates ECSWorld which wraps the flecs::world                  │   │
│   │                                                                     │   │
│   │   3. Godot loads Polaris.tscn autoload                              │   │
│   │      PipelineNode and CompositionFactory enter the tree             │   │
│   │                                                                     │   │
│   │   4. CompositionFactory binds to SceneTree                          │   │
│   │      Connects to node_added/node_removed signals                    │   │
│   │      Collects any existing nodes with composition metadata          │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ FRAME LOOP (Every Frame)                                            │   │
│   │                                                                     │   │
│   │   Godot Callback              What Happens                          │   │
│   │   ─────────────────────────────────────────────────                 │   │
│   │   _input(event)           →   Input systems process player input    │   │
│   │   _physics_process(delta) →   Physics systems run (fixed timestep)  │   │
│   │   _process(delta)         →   Process and render systems run        │   │
│   │                                                                     │   │
│   │   Systems query entities by component, read/write game state,       │   │
│   │   and update Godot nodes through Gd:: components.                   │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ SHUTDOWN                                                            │   │
│   │                                                                     │   │
│   │   1. CompositionFactory unbinds from SceneTree                      │   │
│   │   2. Nodes removed → entities decomposed and destroyed              │   │
│   │   3. PolarisEngine destroys ECSWorld and flecs::world               │   │
│   │                                                                     │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## The ECS ↔ Godot Bridge

Polaris bridges ECS data with Godot's scene tree through **Gd:: components**. These hold pointers to Godot nodes, allowing systems to read/write the visual representation.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   ECS WORLD                              GODOT SCENE TREE                   │
│   (Data & Logic)                         (Visuals & Physics)                │
│                                                                             │
│   ┌─────────────────┐                    ┌─────────────────────┐            │
│   │ flecs::entity   │                    │ CharacterBody3D     │            │
│   │                 │    Gd::Node        │ "Player"            │            │
│   │ ┌─────────────┐ │    ┌───────────┐   │                     │            │
│   │ │ Health      │ │    │ root ─────────────────────────────> │            │
│   │ │ current:100 │ │    └───────────┘   │ ├── MeshInstance3D  │            │
│   │ │ max: 100    │ │                    │ ├── CollisionShape  │            │
│   │ └─────────────┘ │                    │ └── AnimationPlayer │            │
│   │                 │                    │                     │            │
│   │ ┌─────────────┐ │                    └─────────────────────┘            │
│   │ │ Velocity    │ │                                                       │
│   │ │ x: 0, y: 0  │ │    Systems read Velocity, call                        │
│   │ └─────────────┘ │    Gd::Node.set_position() to move                    │
│   │                 │    the CharacterBody3D in Godot.                      │
│   │ ┌─────────────┐ │                                                       │
│   │ │ Tag::Player │ │                                                       │
│   │ └─────────────┘ │                                                       │
│   │                 │                                                       │
│   └─────────────────┘                                                       │
│                                                                             │
│   Data lives in ECS. Godot nodes are the "view" that systems update.        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```

├── src/
│   ├── core/                    # Core singletons and nodes
│   │   ├── Engine.h/.cpp        # Main coordinator
│   │   ├── ECSWorld.h/.cpp      # flecs::world wrapper
│   │   ├── PipelineNode.h/.cpp  # Frame callbacks → ECS
│   │   └── CompositionFactory.h/.cpp
│   │
│   ├── composition/             # Composition base class
│   │   ├── Composition.h/.cpp   # Base (auto-sets Gd::Node for 3D)
│   │   └── TestComposition.h/.cpp
│   │
│   ├── components/              # Built-in ECS components
│   │   └── Gd.h                 # Gd::Node, Gd::Node2D
│   │
│   ├── util/                    # Utilities
│   │   └── Log.h
│   │
│   └── polaris_init.h           # Module entry point
│
├── scenes/
│   └── Polaris.tscn             # Autoload scene
│
└── third_party/
    └── flecs/                   # Flecs ECS library
```

### Your Game Structure

```
game/
├── compositions/                # Your game's entity blueprints
│   ├── Pawn.h/.cpp             # Base pawn with physics, health
│   ├── PlayerPawn.h/.cpp       # Adds input handling
│   └── EnemyPawn.h/.cpp        # Adds AI behavior
│
├── components/                  # Your game's data
│   ├── Data.h                  # Health, Velocity, AIState
│   └── Tags.h                  # Tag::Player, Tag::Enemy
│
├── systems/                     # Your game's logic
│   ├── MovementSystem.cpp
│   ├── CombatSystem.cpp
│   └── AISystem.cpp
│
└── resources/                   # .tres composition instances
    ├── player_pawn.tres        # max_health: 100, move_speed: 5
    └── grunt.tres              # max_health: 50, aggro_range: 15
```
