# Lifecycle

> **L** in CELS — Pipeline and phase execution

> **Note:** For system implementation details, see [4. Systems.md](4.%20Systems.md)

---

## Overview

The **Lifecycle** layer controls **when** systems run. Polaris aligns with Godot's frame callbacks — `_input`, `_physics_process`, and `_process` — ensuring ECS logic runs at the right time with the right delta.

This document covers:
- **Phases** - Execution buckets tied to Godot callbacks
- **Pipeline** - How Godot drives ECS execution
- **Phase Arenas** - Temporary memory that resets each phase

For **how to write systems**, see [4. Systems.md](4.%20Systems.md).

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   GODOT FRAME                          POLARIS PHASES                       │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │
│   │ _input(event)   │ ───────────────> │ Phase_Input     │ → arena reset    │
│   └─────────────────┘                  └─────────────────┘                  │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │
│   │ _physics_process│ ───────────────> │ Phase_Physics   │ → arena reset    │
│   └─────────────────┘                  └─────────────────┘                  │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │

## Phases

Phases map directly to Godot's frame callbacks. Each phase has a dedicated arena for temporary allocations.

| Phase | Godot Callback | Timestep | Arena Size | Use For |
|-------|----------------|----------|------------|---------|
| `Phase_Input` | `_input()` | Event-driven | 64 KB | Input capture, UI events |
| `Phase_Physics` | `_physics_process()` | Fixed (60hz) | 1 MB | Game logic, physics, AI, combat |
| `Phase_Process` | `_process()` | Variable | 512 KB | Animation, interpolation, visuals |

### Phase Definition

```cpp
namespace Polaris {

enum PhaseType {
    Phase_Input,      // _input() - event driven
    Phase_Physics,    // _physics_process() - fixed timestep
    Phase_Process,    // _process() - variable timestep
    Phase_Count
};

struct Phase {
    Arena arena;        // Temporary memory for this phase
    flecs::entity id;   // For system ordering
};

// Runtime is a Godot Object (see 1.2 Core Classes.md)
class Runtime : public Object {
    GDCLASS(Runtime, Object)
public:
    flecs::world world;
    Phase phases[Phase_Count];
    Arena permanent;
    uint64_t frame;
    uint64_t physics_frame;
};

}
```

## Phase Arenas

Each phase has its own arena that **resets automatically** after all systems complete. This provides fast temporary memory for systems.

### Why Phase Arenas?

**Without arenas:**
```cpp
void ai_pathfinding_bad(AI& ai) {
    std::vector<PathNode> open_set;   // malloc every frame!
    std::vector<PathNode> closed_set; // malloc every frame!
    // Run A*...
}  // destructor frees - but this happens 60 times per second per entity!

// With 10 AIPawns: 20 malloc/free calls per frame = 1200/second
// Each malloc/free: ~50-200 cycles = 60,000-240,000 cycles wasted
```

**With arenas (use `.run()` for shared scratch space):**
```cpp
// For arena usage, use .run() to allocate once per batch
static void ai_pathfinding_good(flecs::iter& it) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;

    PathNode* open_set = (PathNode*)arena_alloc(arena, 256 * sizeof(PathNode), alignof(PathNode));
    PathNode* closed_set = (PathNode*)arena_alloc(arena, 256 * sizeof(PathNode), alignof(PathNode));

    while (it.next()) {
        auto ai = it.field<AI>(0);
        for (auto i : it) {
            // Run A* using shared scratch space...
        }
    }
    // NO FREE - arena resets automatically at phase end
}

// With 10 AIPawns: 2 arena allocations total = ~10-20 cycles
// 3000-24000x faster!
```

### Arena Lifetime

```
┌─────────────────────────────────────────────────────────────────────────────┐
│   FRAME LOOP                                                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   _input(event)                                                             │
│   ├── tick(Phase_Input, 0)                                                  │
│   └── arena_reset(input arena)  ←── Input arena freed (reserved for future) │
│                                                                             │
│   _physics_process(delta)                                                   │
│   ├── tick(Phase_Physics, delta)                                            │
│   │   └── world.progress(delta)  ←── ALL ECS systems run here               │
│   │       ├── Phase_Input systems (input capture)                           │
│   │       ├── Phase_Physics systems + sub-phases (game logic)               │
│   │       └── Phase_Process systems (visuals)                               │
│   └── arena_reset(physics arena)  ←── Physics arena freed                   │
│                                                                             │
│   _process(delta)                                                           │
│   ├── tick(Phase_Process, delta)                                            │
│   └── arena_reset(process arena)  ←── Process arena freed                   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

> **Note:** All ECS systems run during `_physics_process()` via a single `world.progress()` call. The default flecs pipeline ensures correct ordering across all phases and sub-phases. Phase arenas still reset after their respective Godot callbacks.

### When to Use Arenas vs Components

**The Rule:** If data needs to **persist beyond the current phase**, use a **component**. If data only lives **during the phase**, use the **phase arena**.

| Scenario | Use | Why |
|----------|-----|-----|
| AI target reference | **Component** | Persists across frames |
| Pathfinding scratch space | **Arena** | Only needed during pathfinding calculation |
| Player health | **Component** | Persists across frames |
| Collision event list | **Arena** | Only needed to process collisions this frame |
| Entity position | **Component** | Persists across frames |
| Sorted entity array | **Arena** | Only needed for this frame's processing |
| Animation state | **Component** | Persists across frames |
| Debug string buffer | **Arena** | Only needed to build UI text this frame |

#### Example: AI Target (Component)

```cpp
// CORRECT: Target persists across frames
struct AI {
    flecs::entity target;  // Stored in component
    AIState state;
};

static void ai_target_acquisition(AI& ai, Gd::Node3D& node) {
    if (!node.is_valid()) return;
    // Find player and store in component
    ai.target = find_nearest_player(node.get_position());
}

static void ai_chase(AI& ai) {
    if (ai.target.is_alive()) {
        // Use target from component - persists from previous frame
    }
}
```

#### Example: Pathfinding (Arena)

```cpp
// CORRECT: Scratch space only needed during calculation
// Use .run() when you need shared scratch space across entities
static void ai_pathfinding(flecs::iter& it) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;

    // Temp data - only lives during this system, shared across all entities
    PathNode* open_set = arena_alloc(arena, 256 * sizeof(PathNode), alignof(PathNode));
    PathNode* closed_set = arena_alloc(arena, 256 * sizeof(PathNode), alignof(PathNode));

    while (it.next()) {
        auto ai = it.field<AI>(0);
        for (auto i : it) {
            // Run A* pathfinding
            // Store RESULT in component, not the scratch data
            ai[i].next_waypoint = calculate_path(open_set, closed_set, ...);
        }
    }
    // open_set and closed_set freed automatically at phase end
}
```

#### Example: Sharing Data Between Phases (Component)

```cpp
// CORRECT: Data shared between Physics and Process phases
struct InterpolationData {
    Vector3 previous_position;
    Vector3 current_position;
};

// Physics phase: Update current position (needs delta_time)
static void physics_update(flecs::iter& it, size_t i,
                           InterpolationData& interp, const Velocity& vel) {
    float dt = it.delta_time();
    interp.previous_position = interp.current_position;
    interp.current_position += vel.linear * dt;
}

// Process phase: Interpolate for smooth visuals
static void process_interpolate(InterpolationData& interp, Gd::Node3D& node) {
    if (!node.is_valid()) return;
    Vector3 interpolated = lerp(interp.previous_position,
                                interp.current_position,
                                alpha);
    node.set_position(interpolated);
}
```

#### Anti-Pattern: Storing Arena Pointers

```cpp
// BAD: Storing arena pointer in component
struct BadAI {
    PathNode* path_nodes;  // DANGER: Points to arena memory!
};

static void bad_system(BadAI& ai) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;
    ai.path_nodes = arena_alloc(arena, ...);  // BAD!
}
// Arena resets → ai.path_nodes is now DANGLING POINTER!

// GOOD: Store the result, not the scratch space
struct GoodAI {
    Vector3 next_waypoint;  // Just the result
};

static void good_system(GoodAI& ai) {
    Arena* arena = &runtime()->phases[Phase_Physics].arena;
    PathNode* temp = arena_alloc(arena, ...);  // Temp scratch space
    ai.next_waypoint = calculate_path(temp);  // Store result only
}
```

class PipelineNode : public godot::Node {
    void _input(const Ref<InputEvent>& event) override {
        runtime_tick(runtime(), Phase_Input, 0.0f);
    }

    void _physics_process(double delta) override {
        runtime_tick(runtime(), Phase_Physics, (float)delta);
    }

    void _process(double delta) override {
        runtime_tick(runtime(), Phase_Process, (float)delta);
    }
};
```

### Runtime Tick

```cpp
void Runtime::tick(PhaseType phase, float delta) {
    // Only run ECS systems during physics phase
    // The default flecs pipeline handles all phase dependencies correctly,
    // including sub-phases created by game systems
    if (phase == Phase_Physics) {
        m_world.progress(delta);
        m_physics_frame++;
    } else if (phase == Phase_Process) {
        m_frame++;
    }

    // Reset phase arena for next frame
    arena_reset(&m_phases[phase].arena);
}
```

**Key Points:**
1. `world.progress()` runs **only during Phase_Physics** — this prevents systems from running multiple times per frame
2. The default flecs pipeline handles all phase ordering, including sub-phases (e.g., PlayerMovement.Input → PlayerMovement.Apply → PlayerMovement.Resolve)
3. Arena resets **after** each phase callback, regardless of whether systems ran
4. Frame counters track physics and process callbacks

## Phase Selection Guide

### Phase_Input - Event-Driven

**When to use:**
- Capturing player input
- UI interactions
- Event handling

**Example:**
```cpp
static void capture_player_input(InputState& input) {
    godot::Input* gd = godot::Input::get_singleton();
    if (!gd) return;
    input.move = gd->get_vector(...);
    input.jump = gd->is_action_just_pressed("jump");
}
```

**Arena usage:** Input event buffers, UI interaction lists

---

### Phase_Physics - Fixed Timestep (60hz)

**When to use:**
- Game logic
- Physics simulation
- AI behavior
- Combat
- Movement

**Example:**
```cpp
static void apply_velocity(const Velocity& vel, Gd::CharacterBody3D& body) {
    if (!body.is_valid()) return;
    body.set_velocity(vel.linear);
    body.move_and_slide();
}

static void resolve_velocity(Velocity& vel, Gd::CharacterBody3D& body) {
    if (!body.is_valid()) return;
    vel.linear = body.get_velocity();
}
```

**Arena usage:** Pathfinding scratch space, spatial query results, damage event lists

---

### Phase_Process - Variable Framerate

**When to use:**
- Visual updates
- Animation
- Interpolation
- Debug rendering
- UI updates

**Example:**
```cpp
static void update_animation(const Velocity& vel, Gd::AnimationPlayer& anim) {
    if (!anim.is_valid()) return;
    float speed = vel.linear.length();
    if (speed > 0.1f) {
        anim.play("walk");
    } else {
        anim.play("idle");
    }
}
```

**Arena usage:** Interpolation arrays, debug strings, particle spawn lists

## Frame Context

The Runtime tracks frame counts for debugging and time-based logic.

```cpp
// For frame-count access, use .run() callback
static void periodic_system(flecs::iter& it) {
    Runtime* rt = runtime();

    // Process frames since start (variable framerate)
    uint64_t frame = rt->frame;

    // Physics frames since start (fixed 60hz)
    uint64_t physics_frame = rt->physics_frame;

    // Run every second at 60hz
    if (physics_frame % 60 == 0) {
        while (it.next()) {
            // Once per second logic for each entity
        }
    }
}
```

## Editor Behavior

PipelineNode disables itself when running in the editor:

```cpp
void PipelineNode::_ready() {
    if (Engine::get_singleton()->is_editor_hint()) {
        set_process(false);
        set_physics_process(false);
        set_process_input(false);
        return;
    }
}
```

**This prevents:**
- ECS systems running during scene editing
- Performance overhead in editor
- Unintended side effects

## Complete Example: Pawn Game Loop

```
PlayerPawn and AIPawn entities exist in the world

Frame N:
├── _input(event)
│   └── tick(Phase_Input) → arena resets (reserved for future use)
│
├── _physics_process(delta)
│   ├── tick(Phase_Physics)
│   │   └── world.progress(delta) ←── ALL systems run here in order:
│   │       │
│   │       ├── Phase_Input systems:
│   │       │   └── CapturePlayerInput (PlayerPawn only)
│   │       │
│   │       ├── Phase_Physics systems + sub-phases:
│   │       │   ├── PlayerMovement.Input sub-phase:
│   │       │   │   ├── PlayerLook
│   │       │   │   ├── PlayerFriction
│   │       │   │   └── PlayerAccel
│   │       │   ├── PlayerMovement.Apply sub-phase:
│   │       │   │   ├── PlayerGravity
│   │       │   │   ├── PlayerJump
│   │       │   │   └── PlayerApply (move_and_slide)
│   │       │   ├── PlayerMovement.Resolve sub-phase:
│   │       │   │   └── PlayerResolve (sync velocity)
│   │       │   ├── AIMovement (AIPawn)
│   │       │   └── AIStateMachine (AIPawn)
│   │       │
│   │       └── Phase_Process systems:
│   │           └── UpdateAnimation (all Pawns)
│   │
│   └── Physics arena resets (pathfinding data, query results freed)
│
└── _process(delta)
    └── tick(Phase_Process) → arena resets (debug strings freed)
```

> **Key insight:** All ECS systems run during `_physics_process()` in a single `world.progress()` call. The flecs pipeline handles ordering via phase dependencies. Sub-phases (like PlayerMovement.Input/Apply/Resolve) provide fine-grained ordering within a domain.

## Summary

| Concept | Description |
|---------|-------------|
| **Phase** | Logical execution bucket for system ordering |
| **Sub-Phase** | Fine-grained ordering within a phase (e.g., PlayerMovement.Input → Apply → Resolve) |
| **Phase Arena** | Temporary memory that resets after each Godot callback |
| **PipelineNode** | Godot Node that calls `tick()` from frame callbacks |
| **tick()** | Resets arena; runs `world.progress()` only during Phase_Physics |
| **Fixed Timestep** | All ECS systems run at 60hz via `_physics_process()` |
| **Variable Framerate** | `_process()` still runs at variable rate for non-ECS work |
