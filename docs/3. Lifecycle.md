# Lifecycle

> **L** in CELS — Execution order control using Pipelines and Phases

---

## Overview

The **Lifecycle** layer controls when systems run. Polaris aligns with Godot's frame callbacks, running ECS logic at the right time in the game loop.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   GODOT FRAME                          POLARIS PIPELINES                    │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │
│   │ _input()        │ ───────────────> │ Input Pipeline  │                  │
│   └─────────────────┘                  └─────────────────┘                  │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │
│   │ _physics_process│ ───────────────> │ Physics Pipeline│                  │
│   └─────────────────┘                  └─────────────────┘                  │
│                                                                             │
│   ┌─────────────────┐                  ┌─────────────────┐                  │
│   │ _process()      │ ───────────────> │ Process Pipeline│                  │
│   │                 │                  │ Render Pipeline │                  │
│   └─────────────────┘                  └─────────────────┘                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## PipelineNode

**Location:** `src/polaris/src/core/PipelineNode.h`

PipelineNode receives Godot's frame callbacks and can run ECS systems.

| Callback | When | Use For |
|----------|------|---------|
| `_input(event)` | Input event received | Input handling systems |
| `_physics_process(delta)` | Fixed timestep (60hz) | Physics, gameplay logic |
| `_process(delta)` | Every frame (variable) | Rendering, interpolation |

---

## Frame Context

PipelineNode tracks frame counts:

| Property | Description |
|----------|-------------|
| `get_physics_frame()` | Physics frames since start |
| `get_process_frame()` | Process frames since start |

## System Registration

Systems are registered with the flecs world and run when the world progresses.

### Basic System

```cpp
// In your game initialization
flecs::world& world = ECSWorld::get()->world();

world.system<Gd::Node3D, Velocity>()
    .each([](Gd::Node3D& node, Velocity& vel) {
        if (node.is_valid()) {
            node.set_position(node.get_position() + vel.linear);
        }
    });
```

### Query-based System

```cpp
world.system<Health>()
    .without<Tag::Dead>()
    .each([](flecs::entity e, Health& hp) {
        if (hp.current <= 0) {
            e.add<Tag::Dead>();
        }
    });
```

---

## Execution Order

Systems run in **registration order** by default. Register systems in the order you want them to execute.

```cpp
// These run in order: Input → Movement → Combat → Animation
world.system("InputSystem").each(...);
world.system("MovementSystem").each(...);
world.system("CombatSystem").each(...);
world.system("AnimationSystem").each(...);
```

---

## Phases (Advanced)

For complex ordering, use flecs phases:

```cpp
// Define custom phases
flecs::entity PrePhysics = world.entity().add(flecs::Phase);
flecs::entity PostPhysics = world.entity().add(flecs::Phase);

// Assign systems to phases
world.system<Velocity>()
    .kind(PrePhysics)
    .each(...);

world.system<Collision>()
    .kind(PostPhysics)
    .each(...);
```

## Editor Behavior

PipelineNode disables itself when running in the editor:

```cpp
void PipelineNode::_ready() {
    if (Engine::get_singleton()->is_editor_hint()) {
        set_process(false);
        set_physics_process(false);
        return;
    }
}
```

This prevents:
- ECS systems running during scene editing
- Performance overhead in editor
- Unintended side effects

## Summary

| Concept | Description |
|---------|-------------|
| **Pipeline** | Groups of systems aligned with Godot callbacks |
| **Phase** | Ordering within a pipeline |
| **PipelineNode** | Godot Node that drives ECS from frame callbacks |
| **Registration Order** | Default execution order for systems |
